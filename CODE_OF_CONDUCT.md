# Code of Conduct

Parleq is a small, focused project. The standard for how people treat each other here is short:

**Be kind. Be patient. Assume good faith. Disagree about ideas, not about people.**

## Expected behaviour

- Use welcoming, inclusive language. Address people the way they ask to be addressed.
- Critique code and design, not the person who wrote it. "This approach has a problem" is fine; ad hominem is not.
- Accept that other contributors have different experience levels, tools, and time budgets. Help newer contributors get oriented.
- When in doubt about tone, err on the side of warmth. Text strips emotional cues; what reads neutral to you may read sharp to someone else.

## Unacceptable behaviour

- Personal attacks, harassment, or sustained disruption of project conversations.
- Discriminatory language or jokes targeting protected characteristics.
- Sharing someone else's private information without permission.
- Repeated bad-faith engagement after being asked to stop.

## Scope

This applies to all project spaces: GitHub issues, pull requests, discussions, commit messages, and any community channels operated under the project's name. It also applies when representing the project externally.

## Enforcement

Concerns can be reported by opening a [GitHub Security Advisory](https://github.com/parleq/parleq-speech/security/advisories/new) (which goes only to the maintainer, not public) or via the contact details on [the maintainer's GitHub profile](https://github.com/jonyoder).

The maintainer will review reports promptly. Possible responses range from a private conversation to temporary restrictions to permanent removal from project spaces, depending on severity and pattern.

Reports will be handled with discretion. Reporters' identities won't be shared without their consent.
